# Endpoints da API — base de estabilização

Inventário do FastAPI carregado desta branch. A tabela descreve contratos do código, não disponibilidade na AWS. São 54 operações declaradas; Swagger/OpenAPI locais são rotas geradas pelo framework e não publicadas pelo gateway team.

Quando `SOCIALMEI_AUTH_ENABLED` está ativa, o middleware resolve identidade/workspace no servidor. Escritas humanas exigem Origin e CSRF; login/cadastro exigem JSON e header do navegador. Sem autenticação ativa, os endpoints CRM operam no workspace configurado do modo compartilhado: esse modo não é uma autorização para atender vários MEIs. Basic do gateway é proteção adicional. A leitura técnica tem Bearer próprio e não seleciona outro workspace.

`INPUT/OUTPUT` usa os modelos publicados no OpenAPI; respostas sem modelo explícito são JSON. Queries usam parâmetros e identificadores internos constantes; tabelas não são selecionadas por texto enviado pelo navegador. HTTP 400/401/403/404/409/422/429/503 e o sucesso são exercitados pelas suites Python conforme o contrato. Não se provoca um 500 na produção para testar tratamento de erro. O endpoint de readiness devolve 503 sanitizado para falha de estrutura/DB.

Os testes reais de duas identidades/workspaces estão em `test_account_auth.py`; operações de estoque, replay, concorrência, exclusão lógica e importação têm suites próprias. A migration 011 adiciona defesa referencial contra SQL direto cruzando workspaces; não é RLS nem substitui autorização.
